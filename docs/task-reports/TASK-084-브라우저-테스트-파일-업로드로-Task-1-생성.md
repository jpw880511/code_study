# TASK-084: 브라우저 테스트 — 파일 하나 업로드로 Task 1 생성

## 상태
완료

## 날짜
2026-11-17

## 작업 요약
실제 브라우저(Playwright, Chromium)에서 프로젝트를 만들고 "새 Task"로 파일 하나(`main.py`)를 올리면 Task 1이 만들어지는지 확인했다. 수동 테스트 대신 다시 실행할 수 있는 E2E 스펙으로 자동화했다.

## 변경 파일
- `frontend/e2e/tasks.spec.ts` (신규, T084~T089 공통)

## TDD 결과
- 검증 항목: 업로드 확인 화면에 `Task 1`과 `main.py` 표시 → 확인 후 목록 카드에 `Task 1`, 제목, `python · 초급 · 파일 1개 · 3줄` 표시 → DB에 `task_number=1`, `upload_method=file`로 저장.
- 결과: 통과. 첫 실행에서 한 번 실패했는데, 스펙의 기대값이 틀려서였다(코드는 4줄이지만 분석기는 빈 줄을 뺀 3줄을 센다 — T066의 의도한 동작). 앱은 맞았고 기대값을 고쳤다.

## 기술 결정
- 개발 서버(5173/8000)와 개발 DB를 그대로 쓰고, 실행마다 고유한 이메일의 임시 계정을 만든다. 종료 시 `users` 행을 지우면 프로젝트, Task, 코드 행이 CASCADE로 함께 지워지고, 스펙이 0건임을 직접 확인한다.
- 테스트마다 자기 프로젝트를 만들어 서로 번호와 목록이 섞이지 않게 했다.
- 화면 확인에 더해 DB를 직접 조회해 서버에 저장되었음을 확인한다.
- 업로드 파일은 서버를 임시 폴더(`UPLOAD_STORAGE_PATH`)로 띄워서 실제 `storage/uploads`에는 쓰지 않았다.
