## 작업 요약
"새 Task" 대화상자에 제목(5~255자), 설명(500자 이하, 남은 글자 수), 탭 3개(파일 업로드/폴더 업로드/코드 붙여넣기), "취소"/"Task 만들기"를 넣었습니다. 제목, 설명, 업로드 규칙을 브라우저에서 먼저 검사하고(파일/폴더는 선택 즉시, 붙여넣기는 제출 시) 오류가 있으면 요청을 보내지 않습니다. 탭을 오가도 입력값이 유지됩니다. 성공하면 "업로드 확인" 화면(FR-019)에서 업로드된 파일 목록(경로 또는 이름, 크기), 제외 안내(브라우저가 거른 것과 서버 `excluded_paths`, 개수 표시), `warnings` 메시지를 보여 주고 "확인"으로 닫습니다. 서버 오류는 서버 메시지와 `suggestion`을 `role="alert"`에 함께 표시하고 대화상자를 유지하며, 예상 밖 오류는 "Task를 만들지 못했습니다. 잠시 후 다시 시도하세요."를 보여 줍니다. 전송 중에는 버튼이 "업로드하는 중..."으로 비활성화됩니다.

## 기술 결정
- 대화상자 내용이 닫히면 언마운트되므로 폼과 확인 화면 상태는 다음에 열 때 초기화됩니다(`CreateProjectModal`과 같은 방식).
- 중복 제출 방지와 대기 상태는 기존 `useFormSubmission`을 재사용했고, `suggestion`만 별도 상태로 추가했습니다.
- (연동 확인 중 수정) 서버 오류가 화면에 있는 상태에서 브라우저 검증에 걸리는 제출을 하면, 이전 서버 오류와 새 검증 오류가 함께 보였습니다. 검증 실패로 `submit()`이 호출되지 않아 서버 오류가 지워지지 않았기 때문입니다. `useFormSubmission`에 `clearError()`를 추가하고(기존 호출부는 영향 없음), 모달이 검증에 실패할 때 서버 오류와 `suggestion`을 지우도록 했습니다. 재현 테스트를 먼저 추가해 RED를 확인한 뒤 고쳤습니다(테스트 399 → 400개).
