## 작업 요약
완료된 문서를 코드와 설명 두 칼럼으로 보여 줍니다. `section`(이름 "학습 문서", `sr-only` h2 포함)은 `grid-cols-1 lg:grid-cols-2`라 데스크톱은 나란히, 좁은 화면은 위아래입니다. 왼쪽은 `CodePanel`(높이 60vh), 오른쪽은 `ExplanationPanel`.

**동기화 설계(재진입 방지)**
- 설명 -> 코드: 4장 항목을 고르면(`selectEntry`) `active = {index, source:'user'}`와 강조 요청(`{file, start, end, nonce}`)을 설정 -> 코드 패널이 그 파일로 바꾸고 줄을 강조하고 스크롤합니다.
- 코드 -> 설명: 코드 패널이 보내는 "보이는 첫 줄"(`followCode`)은 **`active`만 바꾸고 강조 요청은 절대 만들지 않습니다.** 줄 범위가 첫 줄을 포함하는 4장 항목(같은 파일)을 찾아 `{index, source:'code'}`로 두면 그 항목이 강조되고 보이게 스크롤됩니다.
- 되돌림 방지는 세 겹입니다. (1) 한 방향의 결과가 다른 방향의 입력을 만들지 않음(위), (2) 에디터가 사용자 입력 직후의 스크롤만 보고함(TASK-099), (3) 현재 항목이 이미 그 줄을 포함하면 상태를 바꾸지 않음(같은 항목이면 `scrollIntoView`도 다시 하지 않음).
- 설명이 없는 줄(4장이 덮지 않는 줄)로 스크롤하면 현재 항목을 그대로 둡니다(항목이 깜박이지 않게). 항목이 하나도 없어도 오류 없이 동작합니다.
- 여러 파일: 코드 패널이 파일 탭을 바꾸면 그 파일의 1줄을 알려, 그 파일의 항목이 현재로 바뀝니다.

상태별 화면: 상태 확인 중 -> "문서 상태를 확인하는 중..."(`role="status"`). 미완료/없음/실패는 `DocumentStatusView`(TASK-107). 완료 후 문서·코드 로딩 -> "학습 문서를 불러오는 중...", 문서 또는 코드 불러오기 실패 -> `role="alert"` + "다시 시도" 버튼(둘 다 재요청), `content`가 null -> "학습 문서의 내용을 불러오지 못했습니다."(alert). 폴링 중 일시적 실패는 마지막 상태를 유지합니다.

## 실제 Monaco와 실제 백엔드에서의 확인 (2026-11-19)
단위 테스트(가짜 에디터)로는 알 수 없던 부분을 실제 브라우저(Playwright, Chromium)에서 확인했다. 손으로 만든 문서를 DB에 넣어 AI 호출 없이 반복 가능하게 했다.
- 코드 패널(실제 Monaco, 구문 강조, 줄 번호, 읽기 전용)과 설명 패널이 같은 줄에 **나란히** 배치된다(코드 x=16, 설명 x=648).
- 설명 항목을 누르면 코드가 그 줄로 이동하고 그 줄 범위만 강조된다(46~52줄: 강조 7줄, 마지막 한 줄, 4~9줄: 강조 6줄, 범위 길이와 일치).
- 코드를 스크롤하면 설명의 현재 항목이 따라간다(4줄·7줄 → "4~9줄" 항목). 어떤 항목도 덮지 않는 줄에서는 현재 항목이 그대로 유지된다. 맨 위로 되돌아와도 두 패널이 서로를 끝없이 쫓지 않고 안정적이다.
- 외부 도메인 요청 0건(CDN 없음), 로그인 이후 콘솔 오류 0건.
- 실제 Gemini로 만든 문서에서도 업로드 → 대기/진행 표시 → 문서 표시, 7개 챕터 탐색, 2장 카드(최대 5개)가 동작했다(2장 결함은 TASK-103 참고).
- 참고(테스트 방식): Playwright로 한 번에 `-10000`만큼 휠을 굴리면 Monaco는 약 2줄만 움직인다. 일반 사용자 스크롤(여러 번의 휠)은 정상이다. 키보드 PageDown, 터치 관성, 스크롤바 드래그는 실제 브라우저에서 확인하지 않았다.
